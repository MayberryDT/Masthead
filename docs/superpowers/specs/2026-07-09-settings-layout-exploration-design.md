# Settings layout exploration design

## Purpose

Create a disposable visual comparison board for the simplified Settings surface. This supersedes the earlier ten-layout exploration: the board should make five centered, single-card settings compositions easy to compare before changing product UI.

## Scope

- One standalone HTML file under `mockups/`.
- Five static, centered, single-card settings layouts, with no app logic, persistence, routing, or behavior claims.
- Reuse the exact Sidebar Knowledge flow card treatment: steel border, machining lines, square spine nodes, and restrained blue bottom edge.
- Retain the same General, Data, Agent access, Advanced, and Danger zone vocabulary.
- Strip the card to direct controls and actions. The surrounding app canvas remains quiet.

## Layout families

1. A literal full settings spine.
2. A grouped ledger.
3. A wider two-column card.
4. A dense minimal ledger.
5. A wide core with a quiet action rail.

## Constraints

- Settings remains a control surface, not a KPI dashboard.
- The comparison board must not use cards inside cards, oversized heroes, decorative charts, secondary menus, or new visual language.
- The existing user-owned `mockups/sidebar-bottom-five-directions.html` file is out of scope.
- The artifact is throwaway. Once a direction is selected, capture the decision and delete or replace the board rather than promote it to application code.

## Review question

Which single centered card makes the full stripped settings set feel most deliberate and recognizably Masthead?
