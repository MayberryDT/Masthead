Failure Pattern to Eliminate

Turn 01 Framing

The import system needs to behave like a local build pipeline with observable stages.

  • Each job has a scope: source, kind, path, cursor, and consent boundary.
  • Each job reports discovered, processed, imported, skipped, failed, current path, and rate.
  • Each failure is grouped into a readable cause with sample evidence.
  • Completion means a specific stage finished, not that every future stage is done.

Should Sources be organized by coding harness, not local source path?

Recommended answer: yes. The primary flow should ask which coding harness to import from, such as Codex, and how much history to include. Source paths remain advanced diagnostics, provenance, and repair details.

Completion Report Shape

Failure Taxonomy

Group Meaning Default Result
unreadable File missing, permission denied, path changed, symlink blocked. Skip child, keep parent running.
locked SQLite or transcript file is temporarily unavailable. Retry with backoff, then mark child retryable.
malformed JSONL line cannot parse or record shape is invalid. Import valid records, count bad records, sample failures.
schema drift Source exists but parser does not recognize enough structure. Block transcript child, show adapter diagnostic.
excluded User policy excludes source, project, or path. Skip cleanly, do not count as failure.
